# 后端重构待办

项目目标：在现有大模型综合观测展示平台基础上，将后端重构为支持“题库生成 - 模型评测 - 自适应红队 - 应用链路 Trace - 风险知识图谱 - 防护建议 - 回归验证 - 漂移监测”的闭环安全评测与防护平台。

排序原则：

- 实现先后：先修基础设施和数据结构，再扩展红队、Trace、知识图谱、防护建议等能力。
- 难易程度：每个任务标注 `简单`、`中等`、`较难`、`困难`。
- 依赖关系：后续任务依赖前置任务的数据模型、任务队列、模型调用层和权限体系。

### 26. 安全漂移监测

  - 生成漂移告警。
- 验收标准：

## 推荐技术选型

| 方向 | 建议技术 | 说明 |
| --- | --- | --- |
| Web API | Django 5 + Django REST framework | 保留现有技术栈，降低迁移成本 |
| 异步任务 | Celery + Redis | 承载题库生成、评测、红队、报告、回归测试 |
| 实时通信 | Django Channels + Redis | 推送任务进度和红队过程 |
| 红队编排 | LangGraph | 实现多轮自适应攻击状态机 |
| 关系数据库 | MySQL 或 PostgreSQL | 短期保留 MySQL；若重构部署，优先 PostgreSQL |
| 向量检索 | PostgreSQL + pgvector 或 Milvus | 原型期用 pgvector，规模扩大后用 Milvus |
| 知识图谱 | Neo4j Community | 适合风险关系、攻击路径、防护方案查询 |
| 结构化输出 | Pydantic + JSON Schema | 替代正则提取和宽松 JSON 解析 |
| 模型接入 | OpenAI-compatible Gateway | 兼容 OneAPI、本地模型、云端模型 |
| API 文档 | drf-spectacular | 自动生成 OpenAPI 文档 |
| 部署 | Docker Compose | 管理 web、worker、redis、db、neo4j |
| 日志 | Python logging / structlog | 加入 request_id、task_id、trace_id |
