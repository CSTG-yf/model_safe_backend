# 后端重构待办

依据文件：`大模型安全创新比赛实施建议.md`

新版目标：将后端从通用测评平台重构为“面向单个目标模型的安全评测、风险归因与个性化防护策略生成平台”。

当前策略：保留已经完成的基础治理、结构化题库、统一评测任务、ModelGateway、JudgeService 和指标体系；普通评测、越狱评测、RAG 污染沙箱、Agent 工具沙箱的结果统一沉淀为目标模型的风险画像，并生成可在每次用户输入前注入/执行的个性化防护策略包。

## 模型职责边界

- 被评测模型：项目的目标模型，来自 `Project.ai_model_name` 或接口参数 `target_model_name`。
- 平台内置模型：用于攻击生成、裁判评分、防护建议等系统内部能力，来自 `INTERNAL_ATTACK_MODEL_NAME`、`INTERNAL_JUDGE_MODEL_NAME`、`INTERNAL_RECOMMENDATION_MODEL_NAME`。
- 真实执行时禁止用平台内置默认模型兜底为被评测模型；项目没有配置目标模型时，应要求调用方显式传入 `target_model_name`。

## 核心产物：模型个性化防护策略包

平台最终不是只输出分数，而是为项目中的目标模型生成 `ModelProtectionStrategy`。

建议结构：

```text
ModelProtectionStrategy
├─ risk_profile.json              # 模型风险画像：价值观、越狱、RAG、Agent、隐私等风险分布
├─ guard_prompt.md                # 可读的防护提示词片段
├─ guard_policy.json              # 后端可执行的结构化防护策略
├─ rag_guard_rules.json           # RAG 文档可信度、污染指令、敏感信息过滤规则
├─ agent_tool_policy.json         # Agent 工具白名单、参数规则、高危确认规则
├─ output_guard_rules.json        # 输出审查与拒答/改写规则
├─ regression_cases.json          # 针对该模型的回归样例集
└─ policy_report.md               # 面向报告和答辩的策略说明
```

运行方式：

```text
用户输入 -> 读取目标模型策略包 -> 输入防护 -> RAG/Agent 场景规则防护
-> 编译最终 prompt/工具策略 -> 调用目标模型 -> 输出审查 -> Trace 写入
```

第一版不把策略包做成单纯的 skill 或纯 Markdown。Markdown 只用于展示和人工审阅，后端真正执行以 JSON/YAML 结构化策略为准。
